# 집중포화

리그 오브 레전드의 아케이드 모드 **집중포화(Swarm)** 를 브라우저에서 즐기도록 만든 생존 게임입니다.
빌드 도구도 외부 라이브러리도 쓰지 않습니다. 순수 JavaScript + Canvas 2D 로만 돼 있습니다.

**원작의 구조를 그대로 따릅니다.** 이름만 빌려 온 게 아니라 챔피언 수치·사거리·쿨다운,
무기 구성, 진화 조건, 적과 보스, 맵과 기믹이 전부 원작에서 온 것입니다.
수치의 출처는 **[`docs/원작-집중포화-자료.md`](docs/원작-집중포화-자료.md)** 에 정리돼 있습니다.

## 원작에서 가져온 것

- **챔피언 9인** — 징크스 · 세라핀 · 레오나 · 일라오이 · 브라이어 · 야스오 · 리븐 · 오로라 · 자야.
  각자의 **전용 무기**(수치·사거리 원작 그대로), **패시브**, **E**, **R** 을 가집니다.
  체력도 원작 스케일이라 기본 1000, 일라오이 1500, 브라이어 1200이고
  기본 방어력은 레오나 25 → 리븐 20 → 야스오 10 → 원거리 0 입니다.
- **일반 무기 20종** — 귀여운 발사기 · 스태틱의 검 · 얼음작렬 갑옷 · 메아리치는 박쥐칼날 ·
  전투 토끼 석궁 · 토끼 초강력 폭발 · 티.버 · 유미봇 · 절멸자 등 원작 목록 그대로입니다.
- **기본 지속 효과 12종** — 피해량 · 치명타 확률 · 스킬 가속 · 투사체 · 이동 속도 · 최대 체력 ·
  방어력 · 체력 재생 · 범위 크기 · 지속시간 · 획득 반경 · 경험치. 수치도 원작 표 그대로입니다.
- **적(태고족)** — 상어사수 · 독두꺼비 · 화수분 · 거미탄 · 딱정벌레 · 분쇄자 · 용트림 · 해마,
  그리고 정예병. 각각 아펠리오스 포탑 · 심술두꺼비 · 우르곳 · 녹턴 · 푸른 파수꾼 · 코그모 ·
  오른 궁의 산양이 원본입니다.
- **최종 보스 4체** — 렉사이 · 브라이어 · 벨베스 · 아트록스. 패턴이 각자의 실제 스킬입니다.
- **맵 4곳** — 물류 창고 지구 · 외곽 지대 · 지하 세계 실험실 · 상륙지. 기믹도 각자 있습니다.

## 실행

`게임 실행.bat` 을 더블클릭하면 로컬 서버가 뜨고 브라우저가 열립니다. 직접 실행하려면:

```bash
node serve.js 8080
```

`index.html` 을 그냥 더블클릭해도 대체로 동작하지만, 브라우저에 따라 `file://` 에서
localStorage 가 막혀 **영구 강화 기록이 저장되지 않을 수 있습니다.** 서버로 여는 쪽을 권장합니다.

## 조작

| 키 | 동작 |
|---|---|
| `WASD` / 방향키 | 이동 (모바일은 화면을 끌어서 조작) |
| `E` | 기본 스킬. 챔피언마다 다르고, 충전식도 있습니다 |
| `R` | 궁극기 |
| `C` | **자동 조준 / 수동 조준 전환** (우클릭도 같습니다) |
| `Esc` / `P` | 일시정지 |

무기는 **자동으로** 공격합니다. 플레이어가 할 일은 위치 잡기, 조준 방식 고르기, 스킬 사용입니다.
본 모드에선 **기본 공격도 무기로 판정**하므로 **스킬 가속이 곧 공격 속도**입니다.

## 게임 규칙

- 한 판은 **15분**. 15분에 그 지역의 **최종 보스**가 등장하고, 잡아야 승리입니다.
- 지역을 클리어하면 **다음 지역**이 열립니다.
- 적을 처치하면 경험치 구슬과 골드가 떨어집니다. 12초 이상 방치된 드랍은 천천히 따라옵니다.
- 레벨업마다 **3개 중 1개**를 고릅니다 — 무기 또는 기본 지속 효과.
- **무기 5칸**(챔피언 전용 무기가 1칸을 차지), **기본 지속 효과 6칸**. 둘 다 5단계까지.

### 화면 읽는 법

난전에서 헷갈리지 않도록 역할마다 **모양과 색을 고정**했습니다. 새 요소를 추가할 때 이 규칙을 깨지 마세요.

| 보이는 것 | 정체 |
|---|---|
| 회전하는 **붉은 가시** (`ENEMY_SHOT_COLOR`) | 적의 탄환 — 쏜 적이 무슨 색이든 항상 이 모양 |
| 진행 방향으로 **길쭉하고 흰 심이 박힌 탄** | 내 공격 (무기 색은 제각각) |
| 바닥 그림자가 깔린 **하늘색 보석** | 경험치 |
| 바닥 그림자가 깔린 **노란 동전** | 골드 |
| 바닥에서 도는 **프리즘 카드** | 접근 카드 — 무기 진화의 열쇠 |

즉 *날아다니는 것 중 붉고 뾰족한 것만 위험하고*, *바닥에 그림자를 깔고 있는 것은 주우면 되는 것*입니다.

### 성장 구조 (이 게임의 중심)

**원작과 같습니다. 챔피언 스킬은 레벨이 없습니다.**

```
챔피언 ── 패시브 · E · R      판 내내 고정 (능력치 보정만 받습니다)
       └─ 전용 무기           무기 5칸 중 1칸을 차지. 1~5단계

무기 5칸       ── 각 1~5단계 → 조건을 채우면 '최종 진화'
기본 지속 효과 6칸 ── 각 1~5레벨. 능력치이자 **진화의 열쇠**
```

#### 진화 — 세 가지가 동시에 필요합니다

1. 그 무기를 **5단계**까지 올리고
2. 그 무기가 요구하는 **기본 지속 효과를 보유**하고 (원작과 같이 **1레벨이면 충분**합니다)
3. **접근 카드(🃏)** 를 1장 씁니다

접근 카드는 **정예병과 미니 보스**를 잡으면 확정으로 떨어집니다. 미니맵에 보라색으로 표시되고,
보급 상점에서 골드로도 살 수 있습니다. **모아둘 수 있으니** 급하지 않으면 아껴 두세요.

조건을 다 채우면 HUD의 무기 칸이 노랗게 반짝이고, 카드를 주우면 **프리즘 테두리 선택창**이 뜹니다.
무기별 진화 조건은 `data.weapons.js` 의 `evoPerk` 에 있고, 무기 카드에도 표시됩니다.

### 맵

| 지역 | 기믹 | 최종 보스 |
|---|---|---|
| 물류 창고 지구 | 중앙에 **회복 지대** | 렉사이 |
| 외곽 지대 | 좌상단에서 **지원 포격** | 브라이어 |
| 지하 세계 실험실 | 양 끝의 **냉각 장치**가 적을 얼림. 좁은 맵 | 벨베스 |
| 상륙지 | 위아래에서 **지원 포격**. 가장 넓은 맵 | 아트록스 |

**바위·석주**는 플레이어와 적 모두 통과하지 못합니다. 지형을 끼고 도는 것이 중요한 생존 기술입니다.
투사체는 넘어갑니다(막히면 자동 공격 게임에서 답답하기만 하기 때문입니다).
**나무 상자**는 부수면 골드와 회복 물약이 나옵니다.

### 미션과 해금

처음 쓸 수 있는 챔피언은 세라핀·징크스·레오나 셋입니다. 나머지 여섯과 무기 세 종은
미션으로 열립니다 (`data.missions.js`). 판이 끝날 때 자동으로 판정하고 결과 화면에 알려줍니다.

### 화면 배치

원작 집중포화의 UI 배치를 따릅니다.

```
┌────────────────────────────────────────────────┐
│              00:00  [보스 체력바]      💰 ☠ 🃏 │
│                                        자동 조준 │
│                                              Ⅱ │
│                                                │
│                    (전장)                       │
│                                                │
│                                      ┌────────┐│
│                                      │ 미니맵  ││
│         [무기 5칸 아이콘]              └────────┘│
│         [지속 효과 6칸]                          │
│         [초상화] [체력바 / 경험치바]      ( E )( R )│
```

그 아래에 챔피언 초상화(레벨 배지 포함)와 체력·경험치 바가 붙습니다.
좁은 화면에서는 오른쪽 아래 버튼과 겹치지 않도록 왼쪽으로 붙습니다.

### 업그레이드 구매 화면

원작과 같은 배치입니다. 왼쪽에 능력치 카드 격자, 오른쪽에 선택한 항목의 상세,

## 좌표계

**월드 좌표는 리그 오브 레전드 단위입니다.** 챔피언 몸통 반지름이 약 55,
레오나 방패 타격 사거리가 550, 징크스 야옹 야옹이 1500입니다.
2D 는 `CAM_ZOOM`(0.5)으로, 3D 는 `UNIT`(0.01)로 축소해 그립니다.

## 3D 모드 (Three.js)

주소 끝에 **`?3d`** 를 붙이거나 타이틀 화면의 **「3D 모드로 전환」** 을 누르면 켜집니다.

```
http://localhost:8080/?3d
```

### 로직은 하나, 렌더러만 둘

**게임 코드는 3D 전환으로 한 줄도 바뀌지 않았습니다.** `game.js` 는 캔버스를 전혀
모르고, 모든 연출(`g.fx` · `g.beams` · `g.texts`)은 그냥 데이터 배열입니다.
`main.js` 는 렌더러의 **세 함수만** 호출합니다.

| 함수 | 하는 일 |
|---|---|
| `draw(g)` | 한 프레임 그리기 |
| `resize(w, h, dpr)` | 화면 크기 변경 |
| `screenToWorld(g, sx, sy)` | 커서 → 월드 좌표 (2D 는 나눗셈, 3D 는 바닥 레이캐스트) |

이 셋만 맞추면 어떤 렌더러든 꽂힙니다. 교체는 `window.ACTIVE_RENDERER` 한 줄입니다.
Three.js 가 로드되기 전에는 2D 로 그리다가 준비되는 즉시 3D 로 넘어갑니다.

### 좌표 매핑

```
2D (x, y)  →  3D (x * UNIT, 높이, y * UNIT)
```

**y축은 높이 전용**입니다. 게임 로직의 y 는 3D 의 z 로 갑니다.
`UNIT = 0.01` 이므로 씬 1.0 = 리그 오브 레전드 100 단위입니다.
게임 각도(+x 가 0)는 `yawOf(a) = π/2 − a` 로 Three.js Y 회전이 됩니다.

### LoL 룩을 만드는 세 가지

**1. 고정 쿼터뷰** — `PerspectiveCamera(fov 45)` 에 오프셋 `(0, 25, 18)`, 약 54° 부감.
FOV 를 좁혀 원근 왜곡을 줄이면 아이소메트릭에 가까운 그림이 나옵니다.
**카메라는 절대 회전하지 않습니다** — 회전 사원수를 시작할 때 한 번만 정하고
이후로는 위치만 lerp 합니다. 화면 흔들림도 회전이 아닌 평행 이동이라 어지럽지 않습니다.
`game.js` 가 관리하는 2D 카메라를 따라가므로 2D 와 3D 의 시야가 어긋나지 않습니다.

**2. 카툰 셰이딩** — PBR 대신 `MeshToonMaterial` + 계단식 그라디언트 맵(`NearestFilter`).
`LOOK.toonSteps` 가 명암 단계를 정하는데, 가장 어두운 단을 0 이 아닌 66 으로 둬서
그림자가 완전히 검어지지 않게 했습니다. **GLTF 를 불러올 때 `applyToonMaterial()` 이
내부 Mesh 를 순회하며 자동으로 변환합니다** — 텍스처(`map`)와 색은 그대로 살리므로
PBR 로 만든 모델을 그대로 넣어도 핸드페인팅 느낌이 납니다.

**3. 선명한 그림자** — `PCFSoftShadowMap`, `DirectionalLight` 한 방만 비스듬히 강하게
(방향이 하나여야 그림자가 또렷합니다). 앰비언트는 푸른빛 도는 `0x202545` 로 어두운 밤 전장을,
차가운 역광 하나로 실루엣을 띄웁니다.
**그림자 카메라는 매 프레임 플레이어를 따라다닙니다** — 고정해 두면 맵(130 단위)이
그림자 상자(±26)를 벗어나는 순간 그림자가 통째로 사라집니다.

분위기는 `render3d.js` 맨 위의 **`LOOK`** 객체 하나로 모읍니다. 콘솔에서
`Render3D.LOOK.fov = 38; Render3D.applyLook()` 처럼 바로 바꿔 볼 수 있습니다.

| 그림자 | cast | receive |
|---|---|---|
| 잡몹·정예 | ✔ | ✘ (작아서 받아도 안 보이는데 셰이더만 무거워집니다) |
| 지형지물 | ✔ | ✔ |
| 챔피언·보스 | ✔ | ✔ |
| 투사체·전리품·연출 | ✘ | ✘ (unlit 으로 또렷하게) |

### 최적화

적·투사체·전리품·장애물·연출은 전부 **`InstancedMesh` + 슬롯 재사용**으로 그립니다.
매 프레임 `begin() → push()×N → end()` 만 하므로 할당이 없고, 드로우 콜은
**개체 수와 무관하게 '쓰는 모델 종류 수'** 로 고정됩니다.

> 실측: 적 **480마리** + 최종 보스 + 그림자 켠 상태 → **드로우 콜 36개, 4.9ms/프레임**
> (브라우저 패널 기준. 실제 브라우저에서는 더 빠릅니다.)

`end()` 는 `needsUpdate` 만 켜지 않고 `addUpdateRange` 로 **실제로 쓴 구간만** 올립니다.
그냥 두면 풀에 할당해 둔 최대치 전체(수백 KB)를 매 프레임 올리게 됩니다.

### 에셋 매니저와 애니메이션

`js/asset-manager.js` 가 GLTF 로드·복제·풀링과 애니메이션 상태 전환을 맡습니다.
어떤 대상에 어떤 모델을 붙일지는 **`js/data.models.js` 의 `ASSET_MANIFEST`** 한 곳에만 씁니다.

- **비동기 로드** — 같은 모델을 동시에 여러 번 요청해도 네트워크 요청은 한 번뿐입니다.
  판이 시작되면 `preloadForRun()` 이 그 판에 쓸 것만 `Promise.all` 로 미리 받습니다.
  **하나가 실패해도 나머지는 정상 진행합니다.**
- **복제는 `SkeletonUtils.clone`** — `Object3D.clone()` 은 뼈대와 SkinnedMesh 의 연결을
  새 계층으로 다시 잇지 못해, 복제본이 전부 원본 뼈대를 따라 움직이는 사고가 납니다.
- **풀링** — 죽은 적의 리그는 버리지 않고 반납받아 재사용합니다
  (실측: 클론 29개로 108번 재사용).
- **DRACO 지원** — 압축된 `.glb` 도 읽습니다. 디코더는 `vendor/three/jsm/libs/draco/` 에 있습니다.
- **카툰 변환** — 로드 시점에 `MeshToonMaterial` 로 자동 변환합니다(텍스처·색 보존).

`AnimationController` 는 상태 이름(`idle`/`run`/`attack`/`death`)만 알면 되고,
실제 클립 이름 매핑은 매니페스트가 들고 있습니다. 전환은 `crossFadeFrom` 으로 부드럽게 하고,
없는 클립은 자동으로 `idle` → 첫 클립 순으로 대체합니다(클립 이름 대소문자·공백도 눈감아 줍니다).

#### 리그 예산 — 수백 마리 애니메이션 문제

**`SkinnedMesh` 는 `InstancedMesh` 로 묶이지 않습니다.** 잡몹 400마리에 각자 리그를 주면
드로우 콜 400개 + CPU 스키닝 400회가 되어 게임이 멈춥니다. 그래서:

> **플레이어에게 가깝고 등급이 높은 순으로 `RIG_BUDGET`(28)마리만** 스킨 애니메이션을 받고,
> 나머지는 지금까지처럼 `InstancedMesh` 로 그립니다.

화면 중앙은 움직이고 외곽은 정적이라 실제로 보면 거의 티가 나지 않습니다.
예산은 **프레임 시간을 보고 스스로 조절**하므로(6~28), 사양이 낮은 기기에서는
애니메이션 수만 줄고 게임은 그대로 돌아갑니다. 거리에 따라 갱신 주기도 낮춥니다
(LOD 0/1/2 = 매 프레임 / 30Hz / 15Hz — 건너뛴 dt 를 모아 넘기므로 속도는 안 어긋납니다).

| 상황 | 적 수 | 드로우 콜 | 프레임 |
|---|---|---|---|
| 리그 없음 (전부 인스턴싱) | 480 | 36 | 4.9ms |
| 리그 28개 + 그림자 | 488 | 100 | 15.9ms |

### 3D 모델 넣기

`models/` 폴더에 `.glb` 를 넣고 `ASSET_MANIFEST` 의 `modelUrl` 한 줄만 채우면 됩니다.
**파일이 없어도 게임은 정상으로 돌아갑니다** — `fallback` 도형으로 대체합니다.

**배율은 반드시 재고 넣으세요.** 모델마다 원본 크기가 천차만별입니다
(넣어 둔 두 플레이스홀더만 해도 높이가 4.79 와 0.90 입니다):

```js
// 브라우저 콘솔 (F12)
AssetManager.measure('enemies', 'minion', 26)   // 26 = 그 적의 r
```

원본 크기와 **권장 `scale`·`yOffset` 을 계산해 줍니다.
자세한 규약은 **[`models/README.md`](models/README.md)** 를 보세요.

| 대상 | 방식 | 제약 |
|---|---|---|
| 챔피언 · 최종 보스 | 개별 리그 | 스킨 애니메이션 가능. 항상 최고 품질 |
| 잡몹 · 정예 | 리그 예산 안이면 리그, 밖이면 `InstancedMesh` | `animated: true` 일 때만 |
| 지형지물 | `InstancedMesh` | **스킨 없는 단일 메시**여야 합니다 |

현재 `models/` 에는 확인용 플레이스홀더 두 개(three.js 예제의 `RobotExpressive.glb`,
`Soldier.glb`)가 들어 있습니다. 징크스와 일반 미니언에 물려 뒀으니 지금 바로
애니메이션이 도는 걸 볼 수 있고, 진짜 에셋을 구하면 그 줄만 바꾸면 됩니다.

Three.js 는 빌드 단계가 없는 프로젝트라 `vendor/three/` 에 직접 넣어 뒀습니다(r169).
오프라인에서도 돌아가고, `index.html` 의 importmap 이 `three` 를 그리로 연결합니다.

## 내용 추가하기

전부 데이터 파일에 한 덩어리씩 얹으면 됩니다. 등록 목록을 따로 고칠 필요는 없습니다.

**챔피언** — `data.champions.js` 에 항목을 추가하고, 그 챔피언의 전용 무기를 `data.weapons.js` 에
`champOnly: true` 로 넣습니다(그래야 습득 목록에 섞이지 않습니다). 패시브는 필요한 갈고리만
골라 넣으면 됩니다: `init` · `tick` · `onKill` · `onHit` · `onCrit` · `onLevelUp` ·
`asFactor` · `dmgFactor` · `areaFactor`. 패시브가 쓰는 상태값은 전부 `p.px` 에 담고,
공격력·공격 속도·범위에 거는 순간 보정은 factor 로 돌려주세요.
`p.st.asMul` 에 직접 곱하면 누적되어 폭주합니다.

**무기** — `WEAPONS` 에 항목을 추가합니다. `lv` 에 1~5단계 수치, `evoStats` 에 진화 후 수치,
`evoPerk` 에 진화 조건 지속 효과 id 를 적고 `update(g, w, dt)` 에 동작을 씁니다.
현재 단계 수치는 `wst(this, w)` 로 꺼냅니다. 진화 여부는 `w.evolved` 입니다.
피해량에는 `p.st.dmgMul`, 쿨다운에는 `p.st.asMul`, 범위에는 `p.st.areaMul`,
지속시간에는 `p.st.durMul` 을 반드시 반영하세요.
게임이 제공하는 도구: `g.spawnBullet` · `g.damageCircle` · `g.damageArc` · `g.damageLine` ·
`g.spawnZone` · `g.spawnMine` · `g.beam` · `g.nearestEnemy` · `g.toughestEnemy` ·
`g.enemiesInCircle` · `g.aimAngle` · `g.aimTarget` · `g.aimPoint` ·
`g.spawnTentacle` · `g.spawnFeather` · `g.spawnWindwall`.

**기본 지속 효과** — `data.perks.js` 의 `PERKS` 에 추가합니다. `apply(p, lv, g)` 는
**그 레벨에서 추가로 적용할 몫만** 반영해야 합니다(누적값이 아닙니다).
새로 넣었으면 어떤 무기의 진화 조건이 될지 `evoPerk` 에 함께 지정하세요.

**적** — `ENEMY_TYPES` 에 추가한 뒤 `WAVES` 의 시간대별 풀에 `['아이디', 가중치]` 로 넣습니다.
`kind` 는 `chase` / `ranged` / `bomber` / `charger` / `flee` 중 하나이고 `shape` 가 생김새를 정합니다.
**`elite: true` 를 주면 처치 시 접근 카드를 확정으로 떨어뜨립니다.**

**보스** — `BOSSES` 에 추가하고 `data.stages.js` 의 스테이지가 `boss` 로 가리키게 합니다.
`patterns` 에 쓸 수 있는 값은 `charge` · `burrow` · `spray` · `spikes` · `summon` · `rupture` · `laser` 이며,
새 패턴은 `game.js` 의 `bossAI` 에 분기를 추가하면 됩니다.

**지역** — `data.stages.js` 의 `STAGES` 에 추가합니다. `gimmick` 은 `heal` / `freeze` / `cannon`
중 하나이고, 새 기믹은 `game.js` 의 `updateGimmicks` 에 분기를 추가하면 됩니다.

## 균형 조정 지점

- 스폰 속도 — `game.js` 의 `updateSpawning` 첫 줄 `rate`
- 적 체력·피해 증가 곡선 — `game.js` 의 `spawnAt` 안 `mul` 과 `dmg`
- 레벨업 요구 경험치 — `game.js` 의 `xpNeedFor`
- 결정 환산량 — `game.js` 의 `finish`
- 난이도 배수 — `data.enemies.js` 의 `DIFFICULTIES`
- 접근 카드 공급량 — `data.enemies.js` 의 `EVENTS` 에 있는 `elite` 이벤트 수
- 장애물 수 — `data.stages.js` 의 스테이지별 `obstacles`
